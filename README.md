# yt-tagme-bot

Бот на Python, который **находит маленькие/непопулярные YouTube-каналы** в нужных категориях,
проверяет их по строгим правилам и сохраняет результаты в JSON (без базы данных).

Ключевая идея: почти вся рутина (поиск кандидатов, отсев мусора, просмотр кадров, подсчёт
доли подходящих видео) автоматизирована, а дорогая vision-модель вызывается **только для
перспективных видео и только по отдельным кадрам**.

---

## Что делает бот

```
поисковые запросы (yt-dlp / YouTube Data API)
        │
        ▼
тысячи каналов-кандидатов
        │  дешёвые фильтры без AI (Shorts/live/вертикальные, <720p, ≤5с, >10000 просмотров)
        ▼
до 15 видео на канал
        │  ffmpeg извлекает 3 кадра (10% / 50% / 90% длительности)
        ▼
vision-AI оценивает КАДРЫ (не видео целиком) → suitable + категория + артефакты
        │
        ▼
правило ≥30% подходящих видео с ранней остановкой
        │
        ▼
канал проходит → logs/found_channels.json (с лучшей категорией)
```

Бот **не скачивает видео** — только отдельные кадры (JPEG) и метаданные.

---

## Правила отбора (жёстко, без послаблений)

| Правило | Значение |
|---|---|
| Видео на канале | ≥ 10 |
| Доля подходящих видео | **≥ 30%** (`max(1, ceil(total × 0.30))`) |
| Shorts / live / премьеры | запрещены |
| Вертикальные видео | запрещены |
| Разрешение | ≥ 720p |
| Длительность | > 5 сек |
| Просмотры видео | < 10 000 |
| Аниме / анимации | **не берём** (категория исключена из списка, промпта и пула запросов) |

Ранняя остановка: как только подходящих уже хватает — PASS; как только даже все оставшиеся
не дотянут до 30% — FAIL. Остальные видео канала не проверяются.

## Как работает по шагам

### 1. Discovery (поиск кандидатов)

- Поиск идёт через **yt-dlp** (`ytsearchN:<query>`) — без траты квоты поиска YouTube Data API.
- Пул из **~1400 запросов** (базовые + expansion + experiment + расширение на 950).
- За прогон берётся **240 запросов**: 70% базовых + 20% expansion + 10% experiment.
- **Тематическая стратификация**: сначала по одному запросу из каждой темы (explore), затем
  адаптивный приоритет (exploit) по EMA новизны + бонус темы.
- **Бонус непробованных запросов** (`runs=0`): пока запрос не прогонялся — он приоритетнее.
- Дедупликация по `channel_id`, отдельный учёт «уже виденных» каналов для novelty.

### 2. Дешёвый отсев (без AI)

- Канал: ≥ 10 видео.
- Видео: `Shorts/live → out`, `вертикальные → out`, `views ≥ 10 000 → out`, `sd (<720p) → out`,
  `≤ 5 сек → out`, возрастные/региональные ограничения → out, очевидный мусор по заголовку → out.
- «AI-farm» fingerprint по метаданным канала (похожие заголовки, регулярность длительности и
  загрузок) — позволяет раньше отсеивать контентные фермы.

### 3. AI-оценка кадров

- `probe` (yt-dlp) получает прямую ссылку на поток, `ffmpeg` извлекает 3 кадра
  (10% / 50% / 90%). Один probe на видео.
- **Two-stage**: QUICK по 3 кадрам; если модель неуверенна — DEEP добавляет кадры 30%/70%.
- Дорогие вызовы ограничены: кадры, а не видео; two-stage; ранняя остановка по правилу 30%.
- Оценка устойчива к сбоям: `bot-check / 403 / expire / network` → временная ошибка, видео
  откладывается (не портит 30%-правило).

### 4. Выбор категории и сохранение

- Категория канала = «голосование» подходящих видео (частая + уверенная).
- Результат пишется **атомарно** (`tmp` → `replace`) в `logs/found_channels.json`;
  проверенные каналы — в `logs/checked_channels.json` (позволяет переживать рестарты).

## AI-оценка

Оценщики кадров взаимозаменяемы (единый интерфейс `analyze(images) -> FrameAnalysis`):

| Оценщик | Как включается | Особенности |
|---|---|---|
| **MiMo V2.6 Flash** | по умолчанию | OpenAI-совместимый vision API, строгий JSON |
| **DeepSeek** (Messages API) | `DEEPSEEK_ENABLED=true` | ~5 с/видео (быстрее MiMo), картинки — только через `/v1/messages` |
| **Локальный VLM** (SmolVLM2-2.2B, llama.cpp) | `LOCAL_VLM_ENABLED=true` | полностью локально, 4 ГБ VRAM |

Важно: DeepSeek-модели принимают изображения только через **Messages API**
(`{"type":"image","source":{"type":"base64",...}}`), а не через OpenAI `image_url` —
в OpenAI-формате модель отвечает «I don't see an image».

Локальный VLM на 2.2B Q4_K_M дал **60% ложных отказов** на shadow-тесте → для
автоматического отказа не годится, оставлен как опциональный эксперимент.

## Устойчивость

- **Watchdog** (`watchdog.py`): проверяет, что раннер жив и `bot.log` обновляется; при
  зависании/падении — перезапускает. Переживает bot-block-паузы.
- **Инкрементальное сохранение**: найденные и проверенные каналы пишутся сразу и атомарно —
  рестарт/выключение компьютера не теряет прогресс.
- **Bot-block state machine**: NORMAL → SUSPECTED → BLOCKED → RECOVERING, backoff-паузы
  (1800 → 3600 → 7200 с). Не обходит анти-бот, а корректно ждёт.
- **Дедупликация** по `channel_id` и учёт уже проверенных — повторно не тратит AI-вызовы.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
# заполните YOUTUBE_API_KEY, MIMO_API_KEY и (при необходимости) остальное
```

Требуется `ffmpeg` и `ffprobe` в PATH.

## Запуск

```bash

python watchdog.py
```

## Конфигурация

Все настройки — через переменные окружения (`.env`), см. `.env.example`. Ключевые:

| Переменная | Назначение |
|---|---|
| `YOUTUBE_API_KEY` | ключ YouTube Data API v3 |
| `MIMO_API_KEY`, `MIMO_BASE_URL`, `MIMO_MODEL` | MiMo vision |
| `LOCAL_VLM_ENABLED`, `LOCAL_VLM_BASE_URL`, `LOCAL_VLM_MODEL` | локальный VLM (llama.cpp) |
| `MIN_SUITABLE_RATIO`, `MIN_CHANNEL_VIDEOS` | пороги отбора |
| `MAX_VIEWS` | максимум просмотров видео |
| `EVAL_PARALLEL` | параллелизм оценки видео |
| `DISCOVERY_QUERIES_PER_RUN` | сколько запросов за прогон |
| `TARGET_REGION`, `TARGET_CHANNELS` | регион и цель |

Секреты (`.env`, `cookies.txt`) и артефакты (`logs/`, `temp/`, кадры) в `.gitignore` —
в репозиторий не попадают.

## Ограничения

- Bot-check YouTube с датацентровых IP — периодические паузы (лечится backoff, не обходом).
- Скорость на «затухающем» этапе ограничена редкостью хороших каналов, а не AI.
- Локальный VLM на 2.2B Q4_K_M слишком слаб для точной отбраковки (60% false-reject).
- TagMe-селекторы зависят от вёрстки и могут требовать правок.
